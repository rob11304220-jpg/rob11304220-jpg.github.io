# Roadmap

The current product is a small, static personal homepage and technical blog. Keep it fast, content-led, and maintainable. Add capabilities only when a concrete personal project or publishing need justifies them.

## Blog growth

When the blog has enough content to benefit from them, consider RSS, generated article tables of contents, code highlighting, previous/next navigation, an updated date, and richer article structured data. Avoid search, pagination, and taxonomy until the collection is large enough to make them useful.

## Content growth

Prioritize substantive work over interface expansion: publish a full B-Rep surface reconstruction project page, add real results and figures, write related technical articles, add concise research experience, and decide whether the public content should remain bilingual or adopt a consistent primary language.

## Quality automation

As the site grows, consider automated accessibility checks, Lighthouse performance budgets, screenshot regression, and a deliberate dependency-update policy. Keep these checks deterministic and appropriate for a small static site.

These are deferred directions, not active commitments.
